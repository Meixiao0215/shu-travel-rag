# 亲手完成项目的学习路径

你已经掌握 LangChain 基础，本项目将这些组件接成可检查的系统。当前实现是可运行的参考答案，练习的目标是让你能独立解释与修改它。

## 第一课：先检查数据，后讨论模型

打开 `travel_rag/ingest.py`，按 `ingest → extract_pages → table_records → build_articles → build_chunks` 的顺序阅读。

1. 打开 `data/processed/pages.json`，对照原 PDF 第3、4页。
2. 找出二级教授那一行，说明 `None` 为什么代表合并单元格，而不是空标准。
3. 找出第七条跨页的例外条件。解释逐页直接切分为何容易漏掉它。
4. 在 `articles.json` 里查看第十八条的 `pages`，确认它包含审批和报销材料要求。

验收：不看代码，说清 `page`、`article`、`chunk` 三者差别。再写一段小脚本，输出第七条的完整内容与页码。

## 第二课：先看检索结果，不让模型掩盖问题

运行三个命令，自己对比前5条。

```bash
python -m travel_rag.cli search "会议包食宿还能领补贴吗？" --mode bm25
python -m travel_rag.cli search "会议包食宿还能领补贴吗？" --mode vector
python -m travel_rag.cli search "会议包食宿还能领补贴吗？" --mode hybrid
```

在 `retrieval.py` 中找到：

- `LocalEmbeddings`：文档批量编码、问题单条编码、向量归一化。
- `BM25Okapi`：中文分词后按词项匹配。
- `reciprocal_rank_fusion`：把两种排名转换成 `1 / (60 + rank)` 后求和。
- `search`：子块召回后按 `parent_id` 回收完整条款。

练习：先用纸算两个排名 `[A,B,C]` 和 `[B,C,D]` 的融合结果，再独立重写 RRF。

不要直接把 BM25 和向量距离相加：二者数值尺度与含义不同。也不要看到一个文档排名高，就认定它支持问题中的所有条件。

## 第三课：普通 RAG 建立对照

配置 `.env` 后运行 `ask --baseline`。在 `agent.py` 找到：

```python
chain = prompt | model.with_structured_output(
    PolicyAnswer, method="json_mode", include_raw=True
)
```

这一步对应你学过的 LCEL：提示输入 → 模型结构化结果。检索在前面由程序完成。

练习：用3道简单题和2道跨条款题，记录检索证据、最终结论和遗漏条件。先区分“没检索到”和“检索到了但没用对”。

## 第四课：把补查能力交给 Agent

读 `TurnContext.tools()` 和 `create_agent(...)`。两个工具的返回值都是带 ID 的证据数据。

你需要能解释：

1. 模型输出的是工具名称和参数，真正执行 Python 函数的是运行时。
2. 工具结果进入消息序列后，模型才继续生成或补查。
3. `PolicyAnswer` 本身也通过工具调用提交结构化回答。
4. 搜索3次、读页2次的预算限制在程序里；16步上限用于整个图循环。

练习：观察某个实际问题是否真的触发补查。若没有，也可能是初始证据已足够，不能为了展示 Agent 而强迫所有问题多查一次。

## 第五课：引用不是让模型自己编页码

先看 `schemas.py` 的 `Claim`，再看 `validate_evidence`。

模型只返回 `evidence_ids`，文件名、页码和原文由程序回查补齐。测试会把不存在的 ID 拦截。

练习：把一个结论的证据从第24条错换成一个真实存在但无关的条款。理解为什么“ID合法性校验”仍不能证明“语义支撑”。这部分需要人工评阅；可以后续实验判别模型，但不能把判别模型当成真值。

## 第六课：做有意义的对比

先看 `eval/cases.json` 的开发题，不动留出题。运行检索评测并阅读每题结果。

一次只改一个因素，例如：

- 450字符切块改成另一组长度。
- BM25 分词前处理。
- 前5条改成前8条，并分析输入长度、成本与效果。

改动后如果改变了 `chunks.json`，重新建索引。用同一题集和相同模型比较。不要只保留“改进有效”的样例；无改善或退化也是有效结论。

验收：写一页实验记录，包含假设、改动、数据、结果、失败案例和限制。

## 第七课：演示和简历

演示建议控制在3分钟：

1. 一道住宿表格题，展开原文。
2. 一道纵向与横向自驾差异题。
3. 一道会议补助多轮追问。
4. 一道境外问题，观察是否说明范围限制。
5. 展示一张真实检索对比表。

简历描述可在自己完成理解与验证后改写为：

“独立实现高校科研差旅政策 RAG Agent，使用 LangChain、DeepSeek V4 Flash 和本地向量索引；处理 PDF 合并单元格与跨页条款，通过 BM25 与向量混合检索回收完整条款，实现证据溯源、条件追问及有限次数补查。构建人工标注评测样例，对比检索策略并分析失败案例。”

指标只填写你真实测得的结果。个人项目放在项目经历；不要写成未经实际发生的实习交付，也不要声称已经服务学校用户。

## 有余力时再加的功能

按价值顺序选择一项：真实用户题集与独立标注、逐条结论支撑评测、检索重排、原生异步请求、政策版本路由。对当前12页文件，多 Agent、微服务和大型分布式数据库暂时不会自动带来更好的答案。
